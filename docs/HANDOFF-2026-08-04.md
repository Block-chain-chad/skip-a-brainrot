## 3. Engine gotchas bank — this will save you hours

### TweenService does not animate non-GuiObject properties in this place

Four data points across three rounds. `TweenService:Create` on these **runs, reports completion, and
never changes the value** — it sits at its last-set value the whole time:

- `UIScale.Scale`
- `NumberValue.Value`
- `Sound.Volume`
- `GuiObject.BackgroundTransparency`

But **`Frame.Size` and `Frame.Position` tween normally.** That asymmetry is the whole workaround:
anything you want animated must be expressed as a Size/Position change, or driven by a stepped loop.

This silently killed multiple "shipped" animations, including several in the earlier alive-pass
(the breathing claim glow used `BackgroundTransparency`; the currency ticker used a `NumberValue`).
**Anything in the repo history claiming a UIScale / transparency / volume tween works should be
re-verified, not trusted.**

Workaround pattern used three times now — a token-guarded stepped driver:

```lua
token += 1
local myToken = token
task.spawn(function()
    local t0 = os.clock()
    while myToken == token do
        local a = math.clamp((os.clock() - t0) / secs, 0, 1)
        paint(from + span * (1 - (1 - a) ^ 5))   -- Quint out, hand-written
        if a >= 1 then break end
        task.wait()
    end
end)
```

For repeating effects use **one shared Heartbeat registry**, not a loop per element — matching the
convention `UIKit.Builders.ensureRingDriver` already uses.

**This deserves its own investigation round.** It smells like a plugin, a global override, or something
in the kit stomping TweenService. Nobody has looked into the cause.

### Don't hook visibility — poll it in the driver

`GameHUDClient` and `SideRail` both write `LeftRail.Visible`. Hooking both made them flip-flop several
times a second and constantly clear the pulse set. The fix was to ask the instance for effective
visibility each frame from inside the driver, walking ancestors:

```lua
local function isShown(inst)
    local node = inst
    while node and node ~= game do
        if node:IsA("GuiObject") and not node.Visible then return false end
        if node:IsA("ScreenGui") then return node.Enabled end
        node = node.Parent
    end
    return true
end
```

### Studio MCP exec-VM traps

- `require()` in the exec sandbox returns a **fresh module instance** with empty caches — probing state
  through it shows you a different object than the game's.
- **Tweens created in the exec sandbox never tick**, and VM-spawned threads die when the exec context
  ends. A test failing this way says nothing about the code.
- **Editing scripts via the Server VM during Play mode does NOT persist.** This silently wasted a round
  (the sprint button "fix" that stayed silent). Always edit in **Edit** mode.
- `script_grep` on a Folder-typed module errors on `.Source` — filter with `IsA("LuaSourceContainer")`.
- `screen_capture` has been timing out for whole sessions. **The user is the visual verifier** — say so
  rather than claiming a visual result you did not see.
- Only one Studio MCP session works at a time; a second concurrent session gets zero roblox-studio
  tools (port conflict).

### Playtesting

Back-to-back Studio playtests keep loading a **read-only profile** (`profile held by another live
server`). That is `SessionLock` working as designed, but it has blocked verification twice.
**Wait ~90s between runs** (`STALE_AFTER = 90`), or your test loads an empty save and proves nothing.
