## 2. Forge NPC profile — `tools/npc_kit/forge_npc.py`

- **Isolated to npc-01:** `tools/brainrot_forge` is not modified. Segments are `VoxelModel`s at **pitch 0.05** (so every SR-Rig size is exact), baked with the forge's own `bake()` (its per-role/per-model triangle budgets apply unchanged), exported with the forge's `write_glb`/`build_manifest`, plus an NPC manifest (`npc_manifest.json`: parts, joints with `C0/C1`, attachments, collider) for `NpcForge.AssembleHuman` to verify against. The brainrot creature gates (eyes, feet-at-zero, 25-cell minimum) are replaced by `validate_segments`.
- **Sizes come from `NpcRigSpec` (Lua) through the harness** — one source of truth; the profile has no size table of its own.
- **Shape language:** beveled, tapered boxes (never spheres), tapers quantised into 2 steps so flat faces greedy-merge; the head gets the round bevel (0.24), limbs a 2-cell bevel (0.10), feet a toe lift.
- **Exporter naming** is the forge's `<model>__<role>`; the library's body refs are `npc_body_<type>/<Segment>__body` (fixed this pass — the first build silently fell back to primitives, which the render exposed).

## 4. Changes made because of the rendered prototype

1. **Body forge refs** (`NpcLibrary`): `npc_body_<type>/<Segment>__body` — without the exporter's suffix the build fell back to primitives (caught because the first render was boxes).
2. **Shoulder pivot → the torso edge** (`NpcRigSpec`, manifest A2): the pivot-compatibility test proved the approved x = ±1.45 (the arm's centre line) sits 0.35 studs outside the torso; R15 places it where the arm meets the body. Now ±1.10 standard / ±1.25 stout / ±0.95 slight. Elbow/wrist pivots unchanged; part positions unchanged.
3. **Hair cap and fringe raised above the brow line** (`NpcLibrary.HairTousled`): the close-up showed the tousled cap covering Gianluca's brows; the kit rule (nothing below y +0.48 on the head) is now a test.
4. **Veteran placeholder offsets** (`NpcCharacters/VeteranBombardiro`): re-authored on a coherent crocodile-plane stand-in so the *treatment* previews legibly; still placeholders until E-13 returns the real template bounds (the recipe says so).
5. Two harness/test fixes surfaced by the previews: rotated parts (cylinders) need world-AABB bounds; Lua `CFrame` products need a Lua-side helper.

## 5. Visual review notes (for your decision, not applied)

- **Head, silhouette, readability:** the 3.4-head proportion reads chunky without going chibi; the face reads at 20 studs and the hat/scarf/cane read at 40. The beveled meshes clearly read as carved rather than as boxes (compare the first, accidental primitive render).
- **Arms and legs are on the slim side for "chunky":** the approved v1 measures **3.65 studs across the shoulders vs 4.0 on default R15** — the SR body is currently *narrower* than the default avatar it is meant to out-chunk. **D-11 proposal (rendered, not applied):** widths/depths only, heights and the portrait line unchanged — arms 0.92/0.85, hands 0.95, legs 0.95/0.88, feet 0.95×0.6×1.2, head 1.60×1.55×1.40, torso 2.30/2.00, shoulders at ±1.60 → 4.1 across; 2,948 triangles; the side-by-side is `standard-body-v1-vs-v11-proposal.png` / `gianluca-v1-vs-v11-proposal.png`. If adopted, arm overlays (bracers, cuffs) gain +0.15 width through the library `fit` table.
- **Hat:** the floppy brim reads as a boater at 2.3 studs; the mesh pass should widen it to ~2.9 with a droop and a larger pinned flap.
- **Hands:** mitts read; a thumb bump would need a mirrored second mesh (polish, not v1).
- **Veteran:** the layer vocabulary (splint, strap, askew plate, goggles up, medal, chip) reads on the stand-in; nothing about Bombardiro itself is shown or claimed.
