The border stroke on `icon` carried the same tier colour in that fallback case too, so the row's rarity read never blanks out even without a model.

3. `UITheme.stroke(icon, color, thick)` (the older, non-Camp API already used elsewhere in this same file, e.g. `M.medallion`) was used instead of `UITheme.ink(icon, 3)` specifically because `ink` hardcodes its colour to `CF.ink` (dark brown) with no override parameter — `stroke` takes an explicit colour and otherwise matches `ink`'s Border ApplyStrokeMode / Round LineJoinMode, making it the natural way to keep the same visual weight while swapping in the tier colour.

4. No idempotency concern here unlike `styleClose`: `buildSellList` destroys and rebuilds every child Frame of `sellList` at the top of the function on every call (pre-existing code, unchanged), so `icon`, its border stroke, and the viewport or fallback dot are all fresh instances every render. There is nothing to double-create.
